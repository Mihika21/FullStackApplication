HGV
GCC Workforce Master Data & Billing Platform
Content Guidelines & Design System
Version 1.0 | March 2026 | Build Reference

This document is the content, UI language, and interaction-writing reference for the HGV GCC Workforce Master Data & Billing Platform. It translates the approved workforce, compensation, billing, upload, reporting, and role-access requirements into consistent product language.

Document principle
Rule
Source of truth
Business terminology and workflow rules follow the HGV workforce/billing requirements; sample documents are used only as structural references.
People first
Use respectful, clear language for employee and workforce data. Avoid language that feels transactional or punitive.
Operational clarity
Every label, action, status, and validation message should make the next step obvious.
Financial precision
Billing, compensation, and configuration language must distinguish inputs, calculated values, overrides, and external billing.
Role awareness
Content must not imply actions a user role cannot perform.

1. Content Principles
Principle
Implementation rule
Clarity first
Show the information needed for the current task. Prefer plain labels and short helper text over dense explanations.
People first
Use 'employee', 'employee record', and 'workforce' consistently. Avoid unnecessary jargon or language that reduces people to billing units.
Single source of truth
Use consistent master-data names across forms, tables, uploads, reports, and billing views.
Financial transparency
Clearly separate configured rates, employee inputs, calculated billing components, overrides, and totals.
Controlled change
Explain when a value is admin-controlled, role-restricted, historical, or overridden.
Auditability
For consequential actions, communicate what changed, when, and by whom.
Consistency
The same field or status must have the same label and meaning everywhere.
Accessible by default
Use sentence case, descriptive labels, visible focus states, and text that remains understandable without colour.

Do not introduce decorative copy that competes with workforce data, compensation figures, billing values, or operational actions.

5. Global Content Rules
Use sentence case throughout the application.
Do not use all-caps labels, promotional slogans, or unexplained abbreviations.
Use 'Add new' for creating a new controlled master value; do not use 'Create' for dropdown values unless the UI creates a full record.
Use 'Save' when changes persist to the current record; use 'Upload' for file ingestion; use 'Export' for report generation.
Use exact field names from the master-data model in tables and reports.
Keep helper text to one or two short sentences.
Use explicit units: INR, USD, %, annual, monthly, and billing month.
Dates should be displayed in a consistent human-readable format while preserving an unambiguous underlying date value.
Do not expose masked sensitive data in standard views.
Never hide an error only through colour; pair status colour with text and/or an icon.

21. Accessibility Content Rules
Never rely on colour alone to communicate active, warning, error, or permission states.
Form labels must describe the field without relying on placeholder text.
Required fields use a visible asterisk plus accessible required semantics.
Validation messages must be adjacent to the relevant field and understandable by screen readers.
Icon-only actions require accessible names/tooltips.
Use meaningful button labels such as 'Download error report' instead of 'Download' where context is ambiguous.
Tables must preserve readable headers and logical row/column relationships.
Masked PII must remain understandable to authorised users without exposing the underlying value.

28. Confirmed Business Decisions to Preserve in UI Content
Joining Bonus is amortized equally across three billing months: Month 1, Month 2, and Month 3; Month 4 onward is zero.
Variable Pay supports None, Flat %, and Custom Amount. Flat % is calculated on monthly fixed salary.
Billing is calculated for GCC and NOC using salary, applicable margin, facility, user bundle, shift allowance, and joining-bonus components.
Rebadge and Colocation billing uses facility and user bundle components; salary and shift allowance are not used for billing.
Non-GCC Fixed Bid is billed outside the platform.
PMO validated monthly shift allowance can override the Shift Type default for an Employee ID and Billing Month.
New controlled dropdown values are introduced through Add new rather than silently through CSV.
Partial-success uploads are supported: valid rows import while invalid rows are reported with row-level errors.
Sensitive PII is protected and masked in standard views.
Billing configuration is admin-managed and should not require deployment for rate changes.
29. Content QA Checklist
Every page uses the same business term for the same field.
Every primary action describes the actual outcome.
Every required field has a clear label and validation message.
Role-restricted actions are hidden or disabled with an understandable explanation.
Billing figures identify applicable components and overrides.
Joining bonus copy consistently states 3-month amortization.
Variable Pay copy consistently states the selected mode and calculation basis.
Non-GCC Fixed Bid records clearly state that billing is calculated outside the platform.
Upload errors identify row and field where possible.
Sensitive data is not exposed in standard views or unnecessary messages.
Empty, loading, success, warning, and error states are defined for each major workflow.
Exports use the same field names and meanings as the application.
Content remains understandable when colour is removed.
Brand language is professional and human without promotional copy inside operational workflows.
